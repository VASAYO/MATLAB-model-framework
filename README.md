# Спецификация фреймворка моделирования (MATLAB)

## 1. Назначение

Фреймворк представляет собой каркас (scaffold) для организации серийных вычислительных экспериментов в MATLAB. Он решает типовые задачи, возникающие при построении расчётных моделей:

- управление наборами входных параметров (в том числе множественными — для серии прогонов);
- заполнение параметров значениями по умолчанию и их валидация;
- инициализацию и корректное удаление вспомогательных объектов модели;
- логирование хода расчёта в файл;
- сохранение результатов моделирования;
- отображение и (опционально) сохранение графиков.

Ядро фреймворка не содержит прикладной логики моделирования — она добавляется пользователем в специально предусмотренные точки расширения (см. раздел 6). Сам фреймворк — это "рантайм"/оркестратор, который вызывает пользовательский код в правильном порядке и с правильным управлением ошибками, ресурсами и результатами.

## 2. Структура репозитория

```
├── LICENSE
├── functionSignatures.json          # автодополнение аргументов Main() в редакторе MATLAB
├── Main.m                           # точка входа
└── Source/                          # (подразумеваемая папка, добавляется в path)
    ├── CalcAndCheckParams.m
    ├── ClassSaveResults.m
    ├── CreateEmptyPlot.m
    ├── DeleteObjects.m
    ├── HandleContainer.m
    ├── PrepareObjects.m
    ├── ReadSetup.m
    └── SetParams.m
```

> В коде `Main.m` явно указана единственная папка для добавления в path — `Source`. Все перечисленные `.m`-файлы должны находиться в ней (в приложенных файлах они присутствуют "россыпью" — при развёртывании их нужно поместить в `Source/`).

## 3. Точка входа — `Main.m`

### 3.1. Сигнатура

```matlab
Main(varargin)
```

Функция вызывается без выходных аргументов, обмен данными происходит только через файловую систему (логи, `.mat`-файлы результатов).

### 3.2. Параметры (name-value)

| Имя | Тип | Обязательность | Описание |
|---|---|---|---|
| `Path2SetupList` | `char` (путь к папке / `.m`-файлу / `.mat`-файлу) | опционально | Источник наборов параметров. Если не задан — поиск файлов `Setup*.m` в корне модели и в папке `Setups`. |
| `isPause2SelectParams` | `'false'` \| `'true'` (строка) | опционально, по умолчанию `'false'` | Если `'true'`, перед началом расчёта выводит в консоль список найденных наборов параметров и ждёт от пользователя ввода номеров наборов, которые нужно рассчитать. |

Пример вызова:

```matlab
Main('Path2SetupList', 'Setups\MyBatch', 'isPause2SelectParams', 'true');
```

Файл `functionSignatures.json` регистрирует эти параметры для автодополнения в редакторе MATLAB (Function Signatures).

### 3.3. Логика выполнения (пошагово)

1. **Подготовка окружения**
   - `clc`;
   - в path добавляется папка `Source` (`addpath`), путь оборачивается в `HandleContainer` — обёртку-хендл, чтобы им можно было управлять "по ссылке" из callback-функций;
   - заводится флаг `isModeling` (тоже `HandleContainer`) — признак того, что расчёт активной набора параметров идёт прямо сейчас;
   - регистрируется `onCleanup(@() ShutdownFun(...))` — гарантирует, что при любом завершении функции (в т.ч. аварийном, `Ctrl+C`, ошибке) будут удалены добавленные пути и выключен `diary`, а в лог попадёт пометка "Не завершено", если обрыв произошёл во время расчёта.

2. **Определение списка полей структуры параметров**
   ```matlab
   [~, FNames] = SetParams([], 0);
   ```
   `SetParams` возвращает перечень имён верхнеуровневых полей структуры `Params` (см. раздел 4.1), который используется `ReadSetup` для парсинга setup-файлов.

3. **Получение наборов параметров** (`ParamsSets` — `cell`-массив структур), в зависимости от `Path2SetupList`:
   - не задан → `ReadSetup(FNames, 'Russian')` — поиск в папках по умолчанию;
   - указана папка или `.m`-файл → `ReadSetup(FNames, 'Russian', Path2SetupList)`;
   - указан `.mat`-файл → загружается переменная `Params` из файла как единственный набор.

4. **Дополнение и проверка каждого набора**: для `k = 1..N`:
   ```matlab
   ParamsSets{k} = SetParams(ParamsSets{k}, k);
   ParamsSets{k} = CalcAndCheckParams(ParamsSets{k}, k);
   ```

5. **(Опционально) интерактивный выбор наборов** — если `isPause2SelectParams == true`, в консоль выводится нумерованный список (`SaveDirName/SaveFileName` каждого набора), пользователь вводит вектор индексов, `ParamsSets` обрезается до выбранных.

6. **Основной цикл по наборам параметров**. Для каждого набора:
   - создаётся папка результатов `Params.Common.SaveDirName` (если её нет);
   - включается запись лога через `diary` в файл `<SaveDirName>/<SaveFileName>.log` (существующий лог удаляется);
   - `isModeling.Value = true`;
   - в блоке `try/catch`:
     - `Objs = PrepareObjects(Params)` — инициализация вспомогательных объектов;
     - `[Objs, SimData] = MainChain(Objs, Params)` — **основная точка расширения**, куда добавляется прикладная логика моделирования (см. раздел 6.1);
     - `Objs.SaveResults.Step(Params, ...)` — сохранение результатов (см. раздел 5.2);
     - `DeleteObjects(Objs)` — освобождение объектов;
   - при исключении: `isModeling.Value = false`, отчёт об ошибке (`ME.getReport`) пишется в лог, `diary off`, переход к следующему набору (`continue`) — **сбой одного набора не прерывает всю серию**;
   - при успехе: `isModeling.Value = false`, отметка "Завершено" в лог, `diary off`.

### 3.4. Вспомогательные подфункции `Main.m`

| Функция | Назначение |
|---|---|
| `MainChain(InObjs, Params)` | Основная функция расчёта (точка расширения). В текущем виде — только блок отрисовки/сохранения фигур по флагу `Params.Common.isDraw` (перечень фигур `f`/`fNames` пуст — заготовка). |
| `ProcessPaths(Paths, mode)` | Добавляет (`'add'`) либо удаляет (`'rm'`) список путей относительно каталога, где лежит `Main.m`. |
| `ShutdownFun(Paths, isModeling)` | Callback для `onCleanup`: помечает незавершённый расчёт в логе, выключает `diary`, удаляет добавленные пути. |

## 4. Система параметров

### 4.1. Структура `Params`

Единая структура `Params` с верхнеуровневыми полями (на данный момент — только `Common`); список имён полей формируется в `SetParams` и переиспользуется по всему фреймворку:

```matlab
FNames = {'Common'};
```

#### Поле `Params.Common` (устанавливается в `SetParamsCommon`, файл `SetParams.m`)

| Поле | Тип / допустимые значения | По умолчанию | Назначение |
|---|---|---|---|
| `SaveDirName` | `char` | `'Results'` | Папка сохранения результатов и лога. |
| `SaveFileName` | `char` | `sprintf('Results%d', ParamsNumber)` | Имя файла результата (`.mat`) и лога (`.log`). |
| `isDraw` | `0` / `1` / `2` / `3` | `0` | Управление отрисовкой: `0` — не рисовать, `1` — рисовать, `2` — рисовать и сохранить (`.fig`), `3` — рисовать, сохранить и закрыть. |

### 4.2. `SetParams.m` — заполнение значениями по умолчанию

```matlab
[Params, FNames] = SetParams(inParams, ParamsNumber)
```

- Возвращает `FNames` — список имён полей верхнего уровня (используется в `Main.m` и `ReadSetup.m`).
- Для каждого имени поля из `FNames` вызывает одноимённую подфункцию `SetParams<FieldName>(Field, ParamsNumber)`, которая дозаполняет вложенную структуру значениями по умолчанию, если пользователь их не задал (`~isfield(...)`).
- **Точка расширения**: в конце файла оставлен шаблон-заготовка для добавления новых верхнеуровневых полей (`SetParams<FName>`) — по этому шаблону нужно писать функции для новых групп параметров.
- Вызов `SetParams([], 0)` (с пустым `Params`) используется только для получения `FNames`, без реального заполнения.

### 4.3. `CalcAndCheckParams.m` — расчёт производных параметров и валидация

```matlab
Params = CalcAndCheckParams(inParams, ParamsNumber)
```

Точка расширения для:
- вычисления производных/промежуточных параметров на основе введённых пользователем;
- проверки корректности значений (диапазоны, типы, взаимная согласованность) с выбросом информативных ошибок.

В текущей реализации — заготовка-passthrough (`Params = inParams`), логику необходимо добавить под конкретную модель.

### 4.4. `ReadSetup.m` — чтение setup-файлов

```matlab
Params = ReadSetup(FNames, LogLanguage, Source)
```

**Назначение**: найти файлы `Setup*.m` и распарсить их в набор(ы) структур параметров.

**Аргументы**:

| Аргумент | Тип | По умолчанию | Описание |
|---|---|---|---|
| `FNames` | `cell` | `{'Common'}` | Имена полей верхнего уровня структуры `Params` — используются для подстановки префикса. |
| `LogLanguage` | `'Russian'` \| `'English'` | `'Russian'` | Язык сообщений в консоль. |
| `Source` | `char` | `''` | Путь: пусто → поиск `Setup*.m` в текущей папке и в `Setups\`; путь к папке → поиск в ней; путь к конкретному `.m`-файлу → парсинг только его. |

**Формат setup-файла** (`Setup*.m`):

- Обычный `.m`-код (не функция), в котором поля инициализируются **без префикса `Params.`**, например:
  ```matlab
  Common.SaveDirName = 'Results\Case1';
  Common.isDraw = 1;
  % End of Params
  Common.SaveDirName = 'Results\Case2';
  Common.isDraw = 2;
  ```
- Парсер построчно подставляет префикс `BufParams.` перед каждым известным именем поля (`FNames`) и выполняет строку через `eval`.
- Разделитель наборов параметров внутри одного файла — комментарий `% End of Params`. Всё, что написано в строке после него, игнорируется как комментарий.
- Конец файла неявно завершает последний набор (ставить `% End of Params` в конце не обязательно).
- Пустые наборы отбрасываются.
- Разные файлы всегда дают разные наборы параметров.
- Если ни одного набора не найдено (нет файлов или все пустые) — возвращается один пустой набор (расчёт с параметрами по умолчанию).

## 5. Управление объектами и результатами

### 5.1. `PrepareObjects.m` / `DeleteObjects.m` / `HandleContainer.m`

```matlab
Objs = PrepareObjects(Params)
```
Точка расширения: создаёт структуру `Objs`, поля которой — объекты (как правило, `handle`-классы), нужные для одного прогона расчёта. В базовой реализации содержит только:
```matlab
Objs.SaveResults = ClassSaveResults(Params);
```
При добавлении новой прикладной логики сюда добавляются дополнительные поля-объекты.

```matlab
DeleteObjects(Objs)
```
Проходит по всем полям структуры `Objs` и вызывает `delete(...)` для каждого — корректное освобождение `handle`-объектов по завершении прогона.

```matlab
classdef HandleContainer < handle
    properties
        Value;
    end
end
```
Простейшая обёртка, превращающая любое значение (в т.ч. примитив типа `logical` или `cell`) в объект-хендл, чтобы его можно было изменять "по ссылке" внутри вложенных/callback-функций (используется в `Main.m` для `Paths` и `isModeling`).

### 5.2. `ClassSaveResults.m` — сохранение результатов

```matlab
classdef ClassSaveResults < handle
```

| Свойство | Доступ | Описание |
|---|---|---|
| `SaveDirName` | read-only | Папка сохранения (берётся из `Params.Common.SaveDirName`). |
| `SaveFileName` | read-only | Имя файла результата (берётся из `Params.Common.SaveFileName`). |

**Конструктор**: `obj = ClassSaveResults(Params)` — инициализирует свойства из `Params.Common`.

**Метод `Step(obj, varargin)`**:
- при отсутствии папки результатов — создаёт её;
- сохраняет в `.mat`-файл (`<SaveDirName>/<SaveFileName>.mat`) **все переданные аргументы как переменные**, используя их исходные имена в вызывающем коде (`inputname`);
- ⚠️ аргументы должны передаваться **именованными переменными**, а не выражениями/константами — для последних `inputname` вернёт пустую строку и они будут молча проигнорированы (этот нюанс явно указан в комментариях `Main.m`).

Пример:
```matlab
Objs.SaveResults.Step(Params, SimData, SomeOtherVar);
```

### 5.3. `CreateEmptyPlot.m` — создание графического окна

```matlab
[f, ax] = CreateEmptyPlot(FigureName)
```

- `FigureName` (опционально) — если фигура с таким `Name` уже открыта, она закрывается и создаётся заново (гарантия единственности окна с данным именем);
- если имя не задано — создаётся обычная новая фигура;
- фигура создаётся в режиме `WindowStyle="docked"`, белый фон;
- сразу возвращаются готовые `f` (figure) и `ax` (axes) с включёнными `hold on; grid on;`.

## 6. Точки расширения (что нужно дописать под конкретную модель)

| Место | Файл | Что добавить |
|---|---|---|
| Логика расчёта | `Main.m` → подфункция `MainChain` | Основной алгоритм моделирования; заполнение `f`/`fNames` для сохранения графиков. |
| Новые группы параметров | `SetParams.m` | Подфункции `SetParams<FieldName>` по шаблону в конце файла + добавление имени в `FNames`. |
| Валидация/производные параметры | `CalcAndCheckParams.m` | Проверки допустимости значений, расчёт производных величин. |
| Дополнительные объекты модели | `PrepareObjects.m` | Новые поля структуры `Objs` (объекты, которые должны быть удалены через `DeleteObjects` по завершении). |
| Дополнительные пути кода | `Main.m` → переменная `Paths` | Добавление подпапок помимо `Source`. |

## 7. Формат setup-листов — краткая памятка для пользователя

```matlab
% Setup1.m — пример файла с двумя наборами параметров

Common.SaveDirName  = 'Results\RunA';
Common.SaveFileName = 'RunA';
Common.isDraw = 1;
% End of Params

Common.SaveDirName  = 'Results\RunB';
Common.SaveFileName = 'RunB';
Common.isDraw = 3;
```

Файл должен называться `Setup*.m` и лежать либо в корне модели, либо в папке `Setups`, либо быть явно указан через `Path2SetupList`.

## 8. Поток выполнения (сводная схема)

```
Main(varargin)
 ├─ парсинг name-value аргументов
 ├─ addpath(Source) + onCleanup(ShutdownFun)
 ├─ SetParams([],0) → FNames
 ├─ ReadSetup(...) → ParamsSets{1..N}
 ├─ для каждого набора: SetParams → CalcAndCheckParams
 ├─ [опционально] интерактивный выбор наборов
 └─ для каждого выбранного набора:
      ├─ mkdir(SaveDirName); diary on
      ├─ try:
      │    ├─ Objs = PrepareObjects(Params)
      │    ├─ [Objs, SimData] = MainChain(Objs, Params)
      │    ├─ Objs.SaveResults.Step(Params, ...)
      │    └─ DeleteObjects(Objs)
      ├─ catch: лог ошибки → continue
      └─ diary off
```
